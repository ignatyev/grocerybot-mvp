## Новый режим: цены из вашего Chrome (0.4.0)

Добавлено **экспериментальное расширение Chrome** с локальным поиском в авторизованных витринах магазинов. Оно помогает там, где запросы Railway получают HTTP 403. Для установки скачайте репозиторий ZIP, загрузите папку `extension` через `chrome://extensions` (режим разработчика), затем соедините расширение и веб-страницу случайным кодом сопряжения. [Подробная инструкция](extension/README.md).

Это **beta**, не гарантированное подключение всех магазинов. Сайты могут требовать ручной поиск. Расширение считывает только карточки товаров и **не** передаёт cookies/пароли, не оформляет покупок. Тарифы доставки пока не проверяются автоматически. Веб-сайт корректно отличает предварительную цену от полного расчёта.

Сервер поддерживает временную 90-минутную очередь заданий `/api/bridge/{open,connect,queue,pull,complete,status,close}` с 256-битным кодом, хешированием ключа и временным хранением в памяти (без аккаунтов). После рестарта Railway нужно новое сопряжение.

# Grocery Bot MVP — поиск продуктовой корзины

Поиск доступных сервисов по адресу и оптимизация корзины с максимум **двумя доставками**. Вторая доставка выбирается, когда экономия составляет хотя бы **300 ₽** (или без неё невозможно собрать полный список). Допускаются подходящие аналоги, скорость доставки в оценке не участвует.

## Обязательные сервисы

В России всегда учитываются шесть каналов: **Магнит, Пятёрочка, Перекрёсток, ВкусВилл, Купер, Яндекс Еда**. Магазины не исчезают из отчёта из-за отсутствия точки на карте. Другие сети и локальные магазины обнаруживаются с помощью Nominatim и Overpass/OSM. Приложение **не делает вывод**, что ближайший физический магазин обязательно доставляет по адресу.

Каждый сервис показывает статус: цены подтверждены по адресу, найден каталог без доставки, нет адаптера, ошибка запроса или доставка недоступна. В агрегаторах (Купер, Яндекс Еда) цены относятся к конкретным магазинам/витринам, а не к сервису целиком.

## Источники цен (v0.3)

После выбора адреса запускаются **попытки реального поиска** (без имитации цен). Цены, если сервис их отдал, помечаются как **каталожные**, а не как окончательные адресные цены. Если сервис требует вход, возвращает капчу или блокирует серверные запросы, в UI отображается ошибка источника. Отдельно показываются адресные тарифы только если настроен подтверждающий внешний адаптер.

- **Магнит, Пятёрочка, Перекрёсток**: read-only поиск по общедоступным страницам сайтов, извлечение структурированных цен `JSON-LD` *при их наличии*. Если страницы не возвращают структурированные предложения, цены не выводятся. Неофициальный и нестабильный способ; прямые API доставки требуют отдельного подключения.
- **Купер**: анонимные чтения списка магазинов по координатам (`/api/v2/stores`) и товаров (`/api/v2/products`), на основе неофициального открытого клиентского проекта. Защита ServicePipe может отклонить запрос; обход защиты не применяется. Каждый магазин в Купере считается отдельной витриной.
- **Яндекс Еда**: экспериментальный read-only поиск доступных витрин из публичной страницы `/retail`, затем товаров из `/api/v1/menu/search` с геокоординатами. Публичного поддерживаемого потребительского API нет, схема нестабильна. Витрины не приравниваются к прямым магазинам, а доставка неизвестна.

Важно: поисковые запросы ограничены 8 позициями на экспериментальный источник (ВкусВилл получает весь список до 12), до 3 витрин Купера и 4 витрин Яндекс Еды. Запросы к публичным сайтам ограничены по времени, ошибки не скрываются. Варианты с неподтверждённой доставкой не могут получить статус окончательно самого дешёвого заказа.

## Подробности и прежние источники

- **ВкусВилл**: настоящий поиск по публичному MCP `https://mcp.vkusvill.ru/mcp` с ценами товаров. Каталожная цена не подтверждает наличие и адресную цену после входа.
- **Остальные пять обязательных сервисов**: включены read-only попытки запроса открытых публичных каталогов. Для точных адресных цен/условий доставки нужны авторизованные адаптеры, иначе итоговая сумма неизвестна.
- **Дополнительные сети**: определяются по карте (с резервным сервером Overpass) и могут быть подключены через такой же адресный адаптер.
- Вручную можно внести проверенные цены и стоимость доставки для тестирования оптимизации.

**Нельзя гарантировать глобально самую дешёвую корзину, пока все магазины не проверены.** Это явно отображается в интерфейсе. [Контракт подключения магазинов](ADAPTERS.md).

## Запуск

Node.js 22+, без установки npm-зависимостей:

```bash
npm test
npm start
```

Откройте `http://localhost:3000`, введите адрес в России, найдите сервисы, затем введите список товаров и запустите поиск цен.

## Railway

В репозитории есть `Dockerfile`. Выберите **Deploy from GitHub Repo** в Railway, затем создайте публичный домен. Переменная `PORT` задаётся платформой. Для публичного инстанса задайте `GROCERYBOT_USER_AGENT` с контактами приложения по требованиям Nominatim. API геокодирования принимает адрес, не используйте в нём конфиденциальные данные.

Для добавления реальных интеграций настройте `GROCERYBOT_ADAPTERS_JSON` и переменные токенов — подробности в [ADAPTERS.md](ADAPTERS.md).

## HTTP API

- `GET /health` — статус сервера.
- `POST /api/discover` — `{ "address": "Россия, Сочи, ул. Навагинская, 9" }`; возвращает `requiredProviders`, `additionalProviders`, `localStores`, `catalogProviders`.
- `POST /api/search` — `{ "list": "молоко 2 л\nяйца 10 шт", "countryCode": "ru", "address": "...", "point": { ... }, "localStores": [], "allowSubstitutions": true }`; возвращает предложения по строкам и отдельный статус каждого провайдера.
- `POST /api/optimize` — `{ "items": [...], "stores": [...], "providers": [...], "allowSubstitutions": true }`; результат дополнен `coverage`, `globalBestVerified`, `scopeNote`.
- `POST /api/cart/vkusvill` — `{ "items": [{ "sku": "1248", "packages": 1 }] }`.

## Ограничения

- Автоматического подтверждения доставки для всех сетей без специальных авторизованных адаптеров нет. Каталожный поиск может блокироваться антиботом, а неофициальные сайты изменяться.
- Скидки, промокоды, бонусы и точное checkout-ценообразование ещё не реализованы.
- Подбор аналогов пока не проверяет состав, аллергены и другие существенные характеристики; нужна проверка перед оплатой.
- Оптимизация длинных списков (>12 позиций) использует ограниченный перебор и может быть приближённой.
- Геопоиск OpenStreetMap требует соблюдения лимитов и правил сервисов; запросы кэшируются и ограничиваются. Для высокого трафика нужны собственные геосервисы и очередь запросов.

Источники: [ВкусВилл MCP](https://github.com/vkustech/vkusvill-mcp-server-manifest), [Nominatim](https://nominatim.org/release-docs/latest/api/Search/), [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API), [Купер партнёрские API](https://docs.kuper.ru/).

## Ограничения после проверки на реальном адресе (0.3.1)

- HTTP 401/403/429/451 означает, что серверный способ чтения каталога ограничен. В интерфейсе это отдельный статус и ссылка на сайт; бот не делает ложный вывод, что товара нет. После 403 поисковик не повторяет запросы по следующим товарам этого провайдера в той же операции.
- Для автоматических персональных цен потребуется официальный доступ партнёра или авторизованный локальный браузерный агент с разрешения пользователя. Cookie/пароли в Railway отправлять нельзя.
- Когда Overpass недоступен, количество других сетей обозначается «не проверено», а не 0.
- HTML-энтити типа `&nbsp;` в каталоге декодируются, чтобы расчёт фасовок не терял литры и граммы. Позиции с неизвестной единицей и явно заданным количеством исключены из точной оптимизации до уточнения.


## Chrome bridge 0.5 (beta)

Расширение `extension/` улучшено: быстрый обход всей очереди, открытие поиска по кнопке-лупе, подтверждение изменения результатов и корректная очистка товарного названия/цены. Для ВкусВилла используется [страница поиска](https://vkusvill.ru/search/). Сессии и cookies магазинов не передаются приложению. Публикация цен не подтверждает наличие/доставку по адресу. Сложные сайты могут требовать ручного чтения. Обновление требует перезагрузки распакованного расширения через `chrome://extensions`.

## Chrome v0.6: обучение поиску по реальным страницам

Если автоматический поиск не находит поле на сайте, откройте в обычном Chrome реальные результаты поиска (например, «молоко»), затем в popup расширения укажите тот же запрос и нажмите «Запомнить этот поиск». Расширение сохраняет шаблон поискового URL **локально**, только если запрос виден в пути или одном из поисковых параметров URL. На сервер Railway шаблоны не передаются. При отсутствии поискового запроса в URL нажмите «Диагностика открытой вкладки» и передайте обезличенный отчёт разработчику для настройки конкретного сайта. Смотрите [инструкцию расширения](extension/README.md).
